# 本地平台与 RSS

本地方案把网页、候选队列、技术摘要和 RSS 保存在你的电脑上。它不依赖 GitHub 授权，也不要求个人 OpenAI API key。没有 API key 时，论文分析通过一次手动 ChatGPT 文件往返完成。

## 1. 首次启动

需要 Python 3.11 或更新版本，可在终端运行 `python3 --version` 检查。Python 缺失或版本过旧时，先从 [python.org](https://www.python.org/downloads/) 安装。

解压项目后，在 Mac 上双击 `Start_Quantum_Radar.command`，Windows 上双击 `Start_Quantum_Radar.bat`。服务运行时保留它打开的终端窗口。

也可在项目目录打开终端：

```bash
PYTHONPATH=src python3 -m qradar serve --port 8765 --open
```

浏览器地址：

```text
http://127.0.0.1:8765/
```

如果没有自动打开浏览器，手动粘贴此地址即可。若端口被占用，改成 `--port 8766`，并使用相应的新地址和 RSS 地址。

正式存档预置三篇本次 ChatGPT 会话整理的真实论文摘要，均标注了来源和阅读范围；这不是每日自动任务的运行记录。`Preview.html` 另外展示五篇基于论文 abstract 的阅读示例，标注为预览，不计入正式存档。

## 2. 收集真实候选

在本地网页点击 **收集候选**。程序从官方 arXiv API 获取最近论文，根据 `config/profile.json` 中的研究主题与关键词筛选，写入待分析队列。

默认首次回看七天。关键词筛选只是召回候选，不表示论文已经与你的研究相关，也不表示已有 AI 解读。网页分别显示候选收集时间和分析更新时间。

收集需要联网，并可能因 arXiv 响应和分页而花费一些时间。失败时查看网页提示和终端日志；原来的正式摘要存档会保留。再次收集会去重，未分析候选仍在队列中。

## 3. 在 ChatGPT 中分析

1. 在网页点击 **导出待分析材料**，下载 `qradar-analysis-request.txt`。该文本包含研究 profile、待分析论文的元数据与 abstract，以及输出 JSON 的字段要求；它也要求 ChatGPT 在能访问时阅读官方正文，并如实记录证据范围。
2. 将文件上传到 ChatGPT，要求按文件中的指令完成技术分析并提供 JSON 文件。
3. 审阅分析，尤其是任务模型、噪声假设、参数依赖和与你研究的联系。来源只含 abstract 时，不把摘要中未出现的证明步骤或定量结论当作已核实信息。
4. 下载 ChatGPT 返回的 JSON；回到本地网页点击 **导入 ChatGPT 分析**，选择该文件。

程序会验证候选 ID、版本、必填字段、相关性分数、来源网址和分析时间。批次校验失败时不会部分导入；修正 ChatGPT 返回的文件后再试。导出的格式说明比手工拼写字段更可靠，优先让 ChatGPT 遵循该文件。

分析通过后，符合相关性阈值的论文进入正式精选；低于阈值的候选记录为已评估，避免重复处理。未包含在本次分析批次里的候选继续保留。重复导入已经处理过的 ID 会被拒绝。

每批默认最多 30 篇。来源正文较长时，可以分成多轮分析；初次收集的积压也不必一天处理完。

**当前不会自动调用你在浏览器中登录的 ChatGPT，也没有创建每天自动分析的任务。** ChatGPT 网页任务不能直接写入你电脑上的项目文件；当前更新正式存档需要你导入 JSON。

## 4. 订阅本地 RSS

把以下地址添加到同一台电脑上的桌面 RSS 阅读器：

```text
http://127.0.0.1:8765/feed.xml
```

网页的主题订阅入口提供相应 URL。主题 feed 仅在该主题已有正式精选时生成，例如：

```text
http://127.0.0.1:8765/feeds/logical_qec.xml
http://127.0.0.1:8765/feeds/magic_stabilizer.xml
```

| 使用方式 | 能否直接订阅本地地址 | 条件 |
|---|---|---|
| 同一台电脑上的桌面阅读器 | 可以 | 本地服务正在运行；阅读器允许 HTTP 源 |
| Feedly、Inoreader 等云端抓取 | 不可以 | 它们访问不到你电脑的 loopback 地址 |
| 手机或另一台电脑 | 不可以直接使用这个地址 | `127.0.0.1` 指向设备自身 |
| 其他人公开订阅 | 需要另行发布 | 将网页和 feed 放到可访问的服务器 |

关闭电脑或停止服务后，RSS 阅读器无法取得新数据；已经下载的条目是否仍可离线阅读取决于阅读器。重新启动服务会恢复同一地址。导入新摘要后 feed 随网页一起更新，实际显示新条目的时间取决于阅读器多久检查一次。

本地 RSS 文件是标准 XML 文档，但生成文件与向公网提供订阅地址是两个步骤。将来可以使用其他静态托管服务或自己控制的服务器，无需返回 GitHub 方案。发布时要重新使用外部地址构建，不能直接把 loopback 链接当作公开站点地址。

## 5. 保存与备份

`data/state.json` 是正式存档，包含摘要、候选队列和评估记录；`config/profile.json` 保存研究偏好。备份时保留这两个文件，或直接复制整个项目文件夹。`local-public/` 是生成结果，可从存档重新构建。

服务停止后再迁移项目更稳妥。把项目移动到另一处再启动，仍会读取项目内的同一份存档。浏览器页面本身不是存档；关闭标签页不会删除摘要。

## 常见问题

**双击启动文件没有成功。** 在终端进入项目目录，执行上面的 `PYTHONPATH=src` 命令，可直接看到错误信息。确认 Python 版本，以及命令是否从包含 `src/`、`config/`、`data/` 的项目目录运行。

**网页没有新摘要。** 检查是否只完成了候选收集。必须分析并导入 JSON，正式网页和 RSS 才会增加经过分析的精选。低相关性批次可能全部被排除，这时队列会减少，但精选数量不增加。

**RSS 地址打不开。** 确认终端中的服务仍在运行，浏览器能打开同一主机和端口的首页。不要用 `file://` 打开 feed 文件来替代阅读器的 HTTP 订阅。

**能不能每天完全自动更新？** 候选收集可另行配置本机定时运行，但本项目尚未为你的电脑设置定时任务。没有模型 API 或能够读写这份本地存档的外部执行环境时，技术分析仍需手动导入。当前交付的是可用的本地收集、阅读和 RSS 平台。
